# Division DS: components, compact

> One block per component: what it is, how to import it, what it needs, and every prop as `name: type = default`. Full pages with examples: /docs/components/<slug>.md.

## Atoms

### Avatar

A small square that shows who someone is. The name is required, because it's both the alt text (the description screen readers read for an image) and the source of the initials. Without one, an avatar is just an image nobody can identify.

```tsx
import { Avatar, avatarVariants, initialsFrom } from 'src/components/atoms/avatar/Avatar'
```

- `name: string` Required. The source of the fallback initials and the announced name.
- `src: string` Optional image. If it can't load, the fallback takes its place without the layout jumping.
- `size: 'sm' \| 'md' \| 'lg' = 'md'` 24 / 36 / 48px.
- `status: 'online' \| 'away' \| 'busy' \| 'offline'` Whether the person is around. It adds the dot and adds the word to the announced name. Leave it out when you don't know.
- `className: string` Merged with the component's classes. When Tailwind utility classes clash, the later one wins.
- `ref: Ref<HTMLSpanElement>` Passed through to the root element.
- `...rest: Omit<HTMLAttributes<HTMLSpanElement>, 'aria-label' \| 'children'>` Every native span prop except aria-label and children. aria-label is removed from the types rather than quietly overwritten when the page runs. The announced name comes from the sr-only span, and an aria-label on the root would override it. children is removed because the component renders its own image/fallback/sr-only children, so anything passed as children would silently disappear.

Page: /docs/components/avatar.md

### Badge

A small chip that shows a status. It comes in six tones and two emphases, and it always carries a word. A colour on its own isn't a status anyone can read.

```tsx
import { Badge, badgeVariants } from 'src/components/atoms/badge/Badge'
```

- `tone: 'neutral' \| 'signal' \| 'ok' \| 'warning' \| 'hostile' \| 'info' = 'neutral'` The status the badge shows.
- `emphasis: 'solid' \| 'subtle' = 'subtle'` Solid uses the invariant fill (the same in light and dark themes) with its matching ink. Subtle is the outline badge: a 1px border and text in the tone’s theme-adaptive text token, with no fill. There's no separate outline emphasis, because it would be this same look under a second name.
- `size: 'sm' \| 'md' = 'sm'` sm (small) is the chip for everyday interface: rows, cards, tables. md (medium) takes the small control height (32px) and the 14px text step. Use it for a badge next to display-size type, like a price.
- `dot: boolean = false` Adds a marker next to the text.
- `icon: ReactNode` An icon before the text, hidden from screen readers with aria-hidden and sized to the badge. It takes the badge’s colour, so the same contrast pair that covers the text covers it too. It adds to the word. It never replaces it.
- `className: string` Merged with the component classes. If two clash, the later Tailwind utility wins (Tailwind is the CSS framework this system styles with).
- `ref: Ref<HTMLSpanElement>` Passed through to the span element.
- `...rest: HTMLAttributes<HTMLSpanElement>` Any other span attribute. For example, aria-hidden on a count that a label next to it already reads out.

Page: /docs/components/badge.md

### Button

The main control for taking an action. It comes in five variants (one of them a button that looks like a text link) and four sizes, with optional icons on either side of the label. It also draws its own focus ring, the outline that shows which control the keyboard is on. The component places that ring for you, because the bevel (the cut corners) would clip one placed anywhere else.

```tsx
import { Button, buttonVariants } from 'src/components/atoms/button/Button'
```

- `variant: 'primary' \| 'secondary' \| 'danger' \| 'ghost' \| 'link' = 'primary'` Which fill/border treatment to use. link looks like a Link (signal text, underline, no fill, no bevel, no fixed height) but it's still a button. Use it for an action inside a sentence, not for going to another page.
- `size: 'xs' \| 'sm' \| 'md' \| 'lg' = 'md'` 24 / 32 / 40 / 48px (pixels). xs is exactly the 24px minimum target, the smallest area people can reliably click or tap. It isn't a token step (there is no xs control-height token) and it's meant for dense toolbars and table rows. Size has no effect on the link variant, which takes the size of the text around it.
- `fullWidth: boolean = false` Stretches the wrapper as well as the button.
- `loading: boolean = false` Sets aria-busy and aria-disabled, blocks the click and the form submit, and shows the spinner. The button stays focusable.
- `loadingLabel: string = 'Working'` Text that's hidden on screen but read aloud while loading.
- `iconStart: ReactNode` An icon before the label, rendered aria-hidden and sized to the button. The spinner replaces it while loading. It isn't available with asChild: put the icon inside the child element instead.
- `iconEnd: ReactNode` An icon after the label, rendered aria-hidden. It stays while loading. Not available with asChild.
- `asChild: boolean = false` Renders the child element with the button's classes. Use it for links that look like buttons. Combining it with disabled, loading or loadingLabel is a type error, so the code won't compile, instead of quietly doing nothing. A link can't really be disabled or made busy, so those props are removed from the types rather than ignored when the page runs.
- `wrapperClassName: string` Classes for the focus wrapper, not the button.
- `className: string` Merged with the component's classes. When Tailwind utility classes clash, the later one wins.
- `ref: Ref<HTMLButtonElement>` Passed through to the button element.
- `type: 'button' \| 'submit' \| 'reset' = 'button'` A Button never submits a form by accident. Ask for submit on the one that should.
- `...rest: Omit<ButtonHTMLAttributes<HTMLButtonElement>, 'aria-busy' \| 'children'>` Every native button prop except aria-busy. aria-busy is removed from the types rather than quietly overwritten when the page runs. loading is the only thing that sets it, and a loading button saying aria-busy="false" would be a spinning, aria-disabled control telling assistive tech (screen readers and other tools people with disabilities use) that it's idle. children is its own declared prop above, not part of rest.

Page: /docs/components/button.md

### Checkbox

A checkbox with three states: off, on and mixed. Radix (the open-source library of accessible building blocks underneath it) handles the semantics and the keyboard behaviour. The look comes from the system's shape language: a square with no rounding and a tick in ink.

```tsx
import { Checkbox } from 'src/components/atoms/checkbox/Checkbox'
```

- `checked: boolean \| 'indeterminate'` The checked state, when your code controls it.
- `defaultChecked: boolean` The starting state when the checkbox manages itself (uncontrolled). It's narrower than Radix's own boolean \| 'indeterminate'. The tick or dash can only follow a checked value the caller passed in. Radix would track an uncontrolled mixed state internally but never hand it back, so that state is excluded instead of being drawn with the wrong mark.
- `onCheckedChange: (checked: boolean \| 'indeterminate') => void` Runs every time it toggles.
- `disabled: boolean` Takes it out of the tab order and stops it toggling.
- `required: boolean` Uses the browser's built-in form validation.
- `name: string` The field name sent with a native form.
- `value: string \| number \| readonly string[]` The field value sent with a native form.
- `invalid: boolean = false` Sets aria-invalid (an ARIA attribute, from Accessible Rich Internet Applications, that tells screen readers the field has an error) and shows the invalid border.
- `id: string` Pair it with a real label through htmlFor.
- `className: string` Merged with the control's classes. If two clash, the later Tailwind utility wins (Tailwind is the CSS framework this system styles with).
- `ref: Ref<HTMLButtonElement>` Passed through to the Radix root button.
- `...rest: Omit<CheckboxProps, 'aria-invalid' \| 'defaultChecked'>` Every Radix Checkbox.Root prop except aria-invalid, spread onto the root. aria-invalid is removed from the type, so you can't pass it, instead of being quietly overwritten while the page runs. invalid is the only thing that sets both the attribute and the border. defaultChecked is declared again above, narrowed to boolean.

Page: /docs/components/checkbox.md

### Divider

A thin line, with an optional legend (a short text label). When it's only decoration, screen readers skip it. When it marks where a section starts, it's a real separator they announce.

```tsx
import { Divider } from 'src/components/atoms/divider/Divider'
```

- `orientation: 'horizontal' \| 'vertical' = 'horizontal'` Which way the line runs.
- `label: string` Adds a legend and makes the divider more than decoration.
- `className: string` Merged with the component's classes. When Tailwind utility classes clash, the later one wins.
- `ref: Ref<HTMLDivElement>` Passed through to the root element.
- `...rest: Omit<HTMLAttributes<HTMLDivElement>, 'role' \| 'children'>` Every native div prop except role and children. role is removed from the types rather than quietly overwritten when the page runs, because label already decides whether the divider is decorative or structural. children is removed because it behaved two different ways: with no label it rendered inside a decorative separator, and with one it disappeared.

Page: /docs/components/divider.md

### IconButton

A square button with one icon. It uses exactly the same variants as Button (same source code, so the two can't drift apart). It requires a label, because an icon on its own tells a screen reader nothing.

```tsx
import { IconButton } from 'src/components/atoms/icon-button/IconButton'
```

- `label: string` Required. It becomes aria-label. It's required in the types, so an icon button with no name won't compile.
- `variant: 'primary' \| 'secondary' \| 'danger' \| 'ghost' = 'primary'` Which fill/border treatment to use. These are Button’s variants minus link, since an icon has no text to underline.
- `size: 'sm' \| 'md' \| 'lg' = 'md'` 32 / 40 / 48px (pixels), all above the 24px minimum target size, the smallest area people can reliably click or tap. Button’s xs isn't offered: 32px is the smallest this control goes.
- `count: number` A number in a corner badge, like items in a cart or unread notifications. It's added to the accessible name, the name screen readers announce (‘Notifications, 3 unread’). It shows as 99+ past 99 and is hidden at 0 unless showZero is set.
- `countLabel: (count: number) => string = String` Formats the spoken part of the name that comes after the label and a comma: count => `${count} unread`. It always gets the real number, never 99+.
- `showZero: boolean = false` Shows the badge when the count is 0.
- `asChild: boolean = false` Renders the child element with the button's classes. Use it for links that look like icon buttons. Combining it with disabled is a type error, so the code won't compile, instead of quietly doing nothing. A link can't really be disabled, so the prop is removed from the types rather than ignored when the page runs.
- `fullWidth: —` Left out on purpose. An icon button is always square, and stretching it would break that.
- `wrapperClassName: string` Classes for the focus wrapper, not the button.
- `className: string` Merged with the component's classes. When Tailwind utility classes clash, the later one wins.
- `ref: Ref<HTMLButtonElement>` Passed through to the button element.
- `...rest: Omit<ButtonHTMLAttributes<HTMLButtonElement>, 'aria-label' \| 'children'>` Every native button prop except aria-label. aria-label is removed from the types rather than quietly overwritten when the page runs. label is the only source of the accessible name, and an aria-label in rest would beat it. children is its own declared prop above, not part of rest.

Page: /docs/components/icon-button.md

### Input

A single-line text field. It doesn't label itself. The label, help text, error text and the wiring between them are FormField's job. On its own, Input handles the box, its states and the focus ring (the outline that shows which element the keyboard is on). It also has three optional extras inside its right edge: a password reveal, a character counter and a clear button.

```tsx
import { Input, inputVariants } from 'src/components/atoms/input/Input'
```

Requires: A <FormField> around it. On its own the control has no label. FormField adds the label, the help text and the error, and connects their ids.

- `inputSize: 'sm' \| 'md' \| 'lg' = 'md'` Called inputSize because size is already a real HTML attribute on input.
- `invalid: boolean = false` Sets aria-invalid (an ARIA attribute, from Accessible Rich Internet Applications, that tells screen readers the field has an error) and shows the invalid border. It doesn't show any error text.
- `size: number` The browser's own attribute, still available.
- `revealable: boolean = false` On type="password", adds a Show password toggle with aria-pressed. The name stays the same, and the pressed state says whether the password is showing. It goes back to hidden when the form submits. Other types ignore it.
- `showCount: boolean = false` Works with maxLength. It shows 12/80 in mono inside the field and adds it to aria-describedby, the attribute that links extra description to a field. It's merged with any describedby you pass in, which is how FormField keeps its help and error text. It only announces the characters left near the limit (the last tenth, and at least the last three), through a polite live region, an area screen readers read out without interrupting.
- `clearable: boolean = false` Shows a clear button while the field has a value (never when it's disabled or read-only). Clearing fires onChange with an empty value, so a controlled field clears through its own handler. Then it calls onClear, then puts focus back in the input.
- `onClear: () => void` Called after the clear button empties the field.
- `clearLabel: string = 'Clear'` The clear button’s name. If the page has more than one, say what it clears: ‘Clear call sign’.
- `wrapperClassName: string` Classes for the wrapper a field with extras renders. Put width classes here when an extra is on. It does nothing on a bare input.
- `className: string` Merged with the input’s classes. If two clash, the later Tailwind utility wins (Tailwind is the CSS framework this system styles with).
- `ref: Ref<HTMLInputElement>` Passed through to the input element.
- `...rest: Omit<InputHTMLAttributes<HTMLInputElement>, 'aria-invalid' \| 'size'>` Every native input prop except aria-invalid, spread onto the element. aria-invalid is removed from the type, so you can't pass it, instead of being quietly overwritten while the page runs. invalid is the only thing that sets both the attribute and the border. If a caller could set one directly, what you see and what screen readers hear could drift apart. size is declared again above as the native number attribute, because inputSize controls the variant.

Page: /docs/components/input.md

### Kbd

A small keycap that shows a key's name. Making shortcuts easy to find was one of the motifs from the G1 mood board (the project's first approval step) worth keeping: if a surface has a shortcut, the surface says so.

```tsx
import { Kbd } from 'src/components/atoms/kbd/Kbd'
```

- `children: ReactNode` The key's name, for example "Esc" or "⌘".
- `className: string` Merged with the component's classes. When Tailwind utility classes clash, the later one wins.
- `ref: Ref<HTMLElement>` Passed through to the kbd element.
- `...rest: HTMLAttributes<HTMLElement>` Every native attribute, passed onto the kbd element, such as a title, or an aria-label for a symbol key (aria-label is the name screen readers read out).

### Link

A link inside text. It's underlined, because in a paragraph colour alone isn't enough to show that something is a link.

```tsx
import { Link, linkVariants } from 'src/components/atoms/link/Link'
```

- `tone: 'signal' \| 'quiet' = 'signal'` Which colour treatment to use.
- `external: boolean = false` Opens the link in a new tab. It adds target="_blank", the rel hardening (attributes that stop the new page reaching back into yours), a trailing icon and the hidden "(opens in a new tab)" warning. Using it together with target or rel is a type error, so it can't fail silently. external already sets those values, so those props are removed from the type instead of being quietly overwritten while the page runs.
- `href: string` Where the link goes.
- `className: string` Merged with the component classes. If two clash, the later Tailwind utility wins (Tailwind is the CSS framework this system styles with).
- `ref: Ref<HTMLAnchorElement>` Passed through to the anchor element.
- `...rest: AnchorHTMLAttributes<HTMLAnchorElement>` Every native anchor prop.

Page: /docs/components/link.md

### LoadingAnimation

A loading state that fills a whole panel, drawn as an animated instrument dial in WebGL (the browser's graphics engine for drawing with the graphics card). The three dials follow the same rules. They draw themselves from the outside in, and their structure drifts. One mechanism clicks to its next detent using the system's snap easing (the motion where things arrive a little large and settle), and the signal accent colour only appears on the part that shows progress.

```tsx
import { LoadingAnimation } from 'src/components/atoms/loading-animation/LoadingAnimation'
```

- `variant: 'aperture' \| 'gyro' \| 'reticle' = 'aperture'` Aperture: shaded blades stepping round a spinning core. Gyro: nested rings turning against each other. Reticle: a progress ring filling up from a marker at 12 o’clock.
- `size: 'sm' \| 'md' \| 'lg' = 'md'` A 96px, 160px or 240px square (px means pixels). It shrinks with its container below that size, but never grows.
- `label: string` Status text that is hidden on screen. Passing it turns the loader into a live region, an area screen readers announce when it changes.
- `className: string` Merged with the component classes. If two clash, the later Tailwind utility wins (Tailwind is the CSS framework this system styles with).
- `ref: Ref<HTMLDivElement>` Passed through to the root div.
- `...rest: Omit<HTMLAttributes<HTMLDivElement>, 'role'>` Every native div prop except role, for the same reason as Spinner: label is the only thing that sets role="status".

Page: /docs/components/loading-animation.md

### Progress

A progress bar that's either determinate (it knows how far along the task is) or indeterminate (it doesn't). The readout is real text in the DOM (the Document Object Model, the live page structure the browser builds) from the very first render. That's motion token M3's rule, and it means a screen reader, the software that reads the page aloud for blind and low-vision people, never hears a number roll.

```tsx
import { Progress } from 'src/components/atoms/progress/Progress'
```

- `label: string` Required. The bar’s accessible name.
- `value: number \| null` null means indeterminate. The value is clamped to [0, max], so an out-of-range value shows as complete instead of overflowing the track.
- `max: number = 100` The value at which the bar is complete.
- `showValue: boolean = false` Shows the percentage (or "In progress") as a readout.
- `tone: 'signal' \| 'ok' \| 'warning' \| 'hostile' = 'signal'` The fill colour. signal paints accent.signal.fill to match Slider. On the track in light theme that’s a 2.15:1 contrast ratio, below the 3:1 a bar needs when it’s the only sign of progress. So set showValue there.
- `className: string` Merged with the outer wrapper’s classes. Later Tailwind utilities (Tailwind is the CSS framework the system is styled with) win.
- `ref: Ref<HTMLDivElement>` Passed through to the Radix Progress root, which is the bar itself. Radix is the library of accessible building blocks this component sits on.
- `...rest: Omit<HTMLAttributes<HTMLDivElement>, 'children'>` Every native div prop except children, spread onto the outer wrapper, so a molecule can attach a data-testid there. children is typed away because this component draws its own label row and track, and a children prop would be thrown away without any warning.

Page: /docs/components/progress.md

### Radio

Pick one choice from a set. The whole group is a single tab stop, and the arrow keys move inside it. That’s how native radio buttons behave, and it’s most of the reason this is built on a Radix primitive (Radix is a library of accessible building blocks) instead of three styled inputs.

```tsx
import { Radio, RadioGroup } from 'src/components/atoms/radio/Radio'
```

- `value (RadioGroup): string` The selected value, when you control it from outside.
- `defaultValue (RadioGroup): string` The starting value, when the group manages it itself (uncontrolled).
- `onValueChange (RadioGroup): (value: string) => void` Fires when the selection changes.
- `name (RadioGroup): string` The native form field name.
- `required (RadioGroup): boolean` Uses the browser’s native form validation.
- `disabled (RadioGroup): boolean` Disables every option in the group.
- `orientation (RadioGroup): 'horizontal' \| 'vertical'` Sets which arrow keys move between options. The visual layout is still up to className.
- `aria-label / aria-labelledby (RadioGroup): string` One of these is required. They’re ARIA attributes (from Accessible Rich Internet Applications) that give the group a name screen readers announce. A radiogroup with no name is a bug.
- `value (Radio): string` Required. This option’s value.
- `disabled (Radio): boolean` Takes just this option out of selection.
- `id (Radio): string` Pair it with a real label using htmlFor.
- `invalid (Radio): boolean = false` Sets aria-invalid, which tells assistive tech the field has an error, and shows the invalid border.
- `className: string` Merged with the control's classes. Later Tailwind utilities (Tailwind is the CSS framework the system uses) win.
- `ref: Ref<HTMLDivElement> (RadioGroup) / Ref<HTMLButtonElement> (Radio)` Passed through to the Radix root element.
- `...rest: (Radio) Omit<RadioGroup.Item props, 'aria-invalid'>` Every Radix RadioGroup.Item prop except aria-invalid, spread onto the item. aria-invalid is typed away instead of being quietly overridden at runtime, because invalid is the only source of both the attribute and the border. RadioGroup itself excludes nothing. It computes no value of its own that a rest prop could defeat.

Page: /docs/components/radio.md

### ScoreRing

One 0 to 100 score shown as a ring with the number in its centre, split into bands the way Lighthouse (Google’s website audit tool) bands its scores. It’s a meter, so a screen reader, the software that reads the page aloud, hears both the score and its band.

```tsx
import { ScoreRing, scoreBand } from 'src/components/atoms/score-ring/ScoreRing'
```

- `label: string` Required. What’s being scored. It’s both the accessible name and the caption.
- `value: number` Required. 0 to 100, clamped and rounded to a whole number.
- `size: 'sm' \| 'md' \| 'lg' = 'md'` The ring is 56, 96 or 128px (pixels) wide.
- `className: string` Merged with the meter’s classes. Later Tailwind utilities (Tailwind is the CSS framework the system uses) win.
- `ref: Ref<HTMLDivElement>` Points to the meter.
- `...rest: Omit<HTMLAttributes<HTMLDivElement>, 'children'>` Every native div prop except children, spread onto the meter. The ring draws its own content.
- `scoreBand(): (value: number) => 'hostile' \| 'warning' \| 'ok'` The banding the ring uses. It’s exported so a table or a sentence beside the ring agrees with it.

Page: /docs/components/score-ring.md

### Select

A single choice from a list, shown in a portalled listbox (a pop-up list rendered at the top level of the page, so nothing around it can clip it). Options come in as an array instead of as children, because the trigger, the panel and the look of each row are decisions the system makes once, not per use.

```tsx
import { Select } from 'src/components/atoms/select/Select'
```

Requires: A <FormField> around it. On its own the control has no label. FormField supplies the label, the help text and the error, and connects their ids so assistive tech (screen readers and similar tools) reads them together.

- `label: string` Required. The trigger’s accessible name, the name a screen reader announces for it.
- `options: SelectOptionWithIcon[]` { value, label, disabled?, icon? } rows shown in the listbox. Pass this or groups, never both.
- `groups: SelectGroup[]` { label, options }[]: rows under headings. Pass this or options, never both.
- `placeholder: string = 'Select…'` Shown until a value is chosen.
- `value: string` The selection, when you control it from outside. Following Radix’s own convention, pass it together with onValueChange.
- `defaultValue: string` The starting selection, when the select manages it itself (uncontrolled). Pass this or value, never both.
- `onValueChange: (value: string) => void` Fires with the new value when a row is chosen, whether the select is controlled or uncontrolled.
- `disabled: boolean` Disables the whole control.
- `required: boolean` Marks the control as required for form submission.
- `name: string` The form field name, for native form submission.
- `inputSize: 'sm' \| 'md' \| 'lg' = 'md'` Matches Input’s sizes so the two line up.
- `invalid: boolean = false` Sets aria-invalid, which tells assistive tech the field has an error, and shows the invalid border.
- `className: string` Merged with the trigger’s classes. Later Tailwind utilities (Tailwind is the CSS framework the system uses) win.
- `ref: Ref<HTMLButtonElement>` Passed through to the trigger button.
- `id: string` The trigger’s id. FormField sets it.
- `aria-describedby: string` The ids of the help and error text, set on the trigger so a screen reader reads them with it. FormField sets it.
- `triggerProps: Omit<ComponentPropsWithoutRef<'button'>, 'aria-label' \| 'aria-invalid' \| 'className'>` Extra props for the visible trigger button, e.g. data-testid. These are separate from the top-level rest, which goes to Radix’s Root (value, onValueChange, disabled, required, name, dir, form…) and never reaches an element on the page. aria-label and aria-invalid are typed away instead of being quietly overridden at runtime, because label and invalid already decide those.
- `...rest: Omit<Select.Root props, 'children'>, minus every aria-* key and data-testid` Radix’s Root control props only. Every aria-* attribute and data-testid are typed away at the top level, because Root renders no element on the page, and anything that lands there vanishes with no error anywhere. Send them through triggerProps instead. children is typed away because this component renders its own Trigger and Portal.

Page: /docs/components/select.md

### Skeleton

A loading placeholder shaped like the content it stands in for: lines of text, a cut-corner block, or an Avatar’s footprint. The shapes themselves are silent. SkeletonGroup is what tells people the region is loading.

```tsx
import { Skeleton, SkeletonGroup } from 'src/components/atoms/skeleton/Skeleton'
```

- `shape: 'text' \| 'block' \| 'avatar' = 'text'` What the placeholder stands in for.
- `lines: number = 1` Text only. The number of lines. Anything below 1 counts as 1.
- `size: 'sm' \| 'md' \| 'lg' = 'md'` Avatar only. Matches Avatar’s size prop.
- `className: string` Merged with the component classes. A block takes its width and height from here.
- `ref: Ref<HTMLDivElement>` Passed through to the root element.
- `...rest: Omit<HTMLAttributes<HTMLDivElement>, 'children'>` Every native div prop except children, because a skeleton draws its own shapes.
- `label (SkeletonGroup): string = 'Loading…'` The hidden words a screen reader hears instead of the shapes.
- `className (SkeletonGroup): string` Lay the placeholders out here, the way the real content will be laid out.
- `ref (SkeletonGroup): Ref<HTMLDivElement>` Passed through to the container.
- `...rest (SkeletonGroup): HTMLAttributes<HTMLDivElement>` Every native div prop.

Page: /docs/components/skeleton.md

### Slider

A value or a range picked on a track. Each thumb (the handle you drag) gets its own name. If a range slider shared one name, a screen-reader user (someone using software that reads the page aloud) would get two controls called the same thing.

```tsx
import { Slider } from 'src/components/atoms/slider/Slider'
```

- `label: string` Required. Applied to each thumb. A single thumb gets it as-is, and a range adds "minimum" / "maximum" to the end.
- `value: number[]` The value(s), when you control them from outside. One number makes a single slider; two make a range.
- `defaultValue: number[]` The starting value(s), when the slider manages them itself (uncontrolled).
- `onValueChange: (value: number[]) => void` Fires as the thumb moves.
- `min: number = 0` The lowest value.
- `max: number = 100` The highest value.
- `step: number = 1` The increment for both snapping while dragging and the arrow keys.
- `disabled: boolean` Takes it out of the tab order and blocks input.
- `formatValue: (value: number) => string` One function feeds both the readout and aria-valuetext (the ARIA, or Accessible Rich Internet Applications, attribute a screen reader speaks as the value). So the spoken value and the printed one can’t drift apart, whether the slider is controlled or not.
- `showValue: boolean = false` Shows the current value(s) as a readout.
- `className: string` Merged with the outer wrapper's classes. Later Tailwind utilities (Tailwind is the CSS framework the system uses) win.
- `ref: Ref<HTMLSpanElement>` Passed through to the Radix Slider root. Radix is the library of accessible building blocks this sits on.
- `...rest: Omit<Slider.Root props, 'aria-label' \| 'aria-labelledby' \| 'children'>` Every Radix Slider.Root prop except those three, spread onto the root. aria-label and aria-labelledby are left out because the accessible name lives on each thumb, where label puts it. - `size: 'md' \| 'sm' = 'md'` sm is the stat-card size: a short sparkline with no axes or grid, and the caption under it. Pair it with headline.
- `headline: string` A formatted figure printed large under the title.
- `centerLabel: string` Donut only. The caption under the total in the centre of the ring.
- `formatValue: (value: number) => string = Intl.NumberFormat('en-IE')` Formats numbers in the tooltip and the table. It formats the y-axis too, unless you give formatAxisValue.
- `formatAxisValue: (value: number) => string = formatValue` Formats only the y-axis tick labels. Use a shorter, compact formatter when formatValue's output is too wide for the axis. SpendChart's compact euro formatter is one example.
- `axisWidth: number = 48` The width the y-axis reserves, in px (pixels). 48 is Recharts' own YAxis default. Make it bigger if formatAxisValue's labels still get cut off.
- `bands: { from: string \| number; to: string \| number; label?: string }[] = []` Line and bar only. Shades stretches of the x-axis, such as night hours on a 24-hour chart. from and to are x-axis values (values of xKey), both included. When from comes after to in the data, the band wraps past the end: 22:00 to 06:00 shades 22:00 to the last point and the first point to 06:00. A band naming a value that isn't in the data is skipped. Every band is listed under the chart with its label, so screen readers hear it too.
- `limits: { value: number; label?: string }[] = []` Line and bar only, not at size sm. Draws a dashed horizontal line at a y value, such as an alert limit of 35 µg/m³. The y-axis grows to include it, so a limit above every data point stays in view. Every limit is listed under the chart with its label and its value formatted by formatValue, so screen readers hear it too.
- `headingLevel: 2 \| 3 \| 4 = 3` Pick the level that fits the page's heading outline.
- `className: string` Merged with the Card classes. Later Tailwind utilities win.
- `ref: Ref<HTMLElement>` Points at the section element.
